# Подробные Telegram-уведомления об Изменениях

## Destination

Получить implementation-ready спецификацию подробных текстовых Telegram-уведомлений, согласованную с существующим Сравнением приложения и достаточную для последующего вызова `/to-spec`, а затем `/to-tickets`. Реализация в рамках карты не выполняется.

## Notes

- Перед каждой сессией читать `AGENTS.md`, `CONTEXT.md`, `docs/agents/issue-tracker.md` и релевантный код.
- Использовать `domain-modeling` для новой терминологии и `codebase-design` для выбора существующих архитектурных швов.
- Единственным источником классификации текстовых Изменений должно оставаться существующее backend-Сравнение; отдельный diff-алгоритм для Telegram запрещён.
- Telegram-сообщение остаётся plain text; изображения, файлы, HTML/PDF и внешние LLM исключены.
- Подробности предназначены только для Telegram. Интерфейс приложения и содержимое центра Уведомлений менять не требуется.
- При Изменении структуры без изменения видимого текста отправлять базовое уведомление с пояснением: «Изменилась структура отслеживаемой области. Изменений видимого текста не обнаружено».
- Ошибка подготовки подробностей не блокирует базовое уведомление и должна попасть в существующий технический журнал.
- `/to-spec` можно вызывать только когда все дочерние билеты разрешены, открытых вопросов и содержимого в `Not yet specified` не осталось.

## Decisions so far

- [Картировать существующее Сравнение и семантику текстовых Изменений](issues/01-map-existing-comparison.md) — единым backend-источником остаётся `compareSnapshots`; `insert`/`delete` прямые, `omitted` означает неполноту, а `replace` является детерминированной позиционной, но не семантической парой.
- [Картировать текущий путь Telegram-доставки и его ограничения](issues/02-map-telegram-delivery.md) — текущая схема уже позволяет получить оба Снимка по сохранённому `check_id`; sender использует plain text и multipart, а преждевременное ограничение Website Change Monitor составляет 3000 code points.
- [Выбрать общий поток данных и внутреннюю проекцию Изменений](issues/03-design-shared-diff-projection.md) — Подробности Изменения содержат только упорядоченные удаления и добавления; `replace` раскладывается в обе секции, а dispatcher получает пару Снимков по `checkId` без миграции.
- [Определить формат сообщения, бюджет, сокращение и fallback](issues/04-design-message-budget-and-fallback.md) — Подробности ограничены 300 code points с распределением 150/150 и явным маркером неполноты; любая ошибка расширения логируется и оставляет базовое Уведомление доставляемым.
- [Проверить реализационные швы и полный набор автоматизированных тестов](issues/05-verify-implementation-readiness.md) — изменение локализовано в Telegram delivery path без миграции, UI или нового HTTP-контракта; сценарии и проверки полностью определены, карта готова к `/to-spec`.

## Out of scope

- Размещение приложения в интернете, VPS, облачный хостинг и удалённый доступ.
- Изменения desktop/mobile-интерфейса, новые страницы, маршруты и query-параметры.
- Вертикальный diff или иные изменения отображения Сравнения.
- Скриншоты, изображения, PDF, HTML и другие вложения.
- Предметно-ориентированная логика для вакансий, товаров, новостей или иных типов страниц.
- Внешняя LLM для пересказа Изменений.
- Изменение расписания Проверок и перенос мониторинга с локального компьютера.
