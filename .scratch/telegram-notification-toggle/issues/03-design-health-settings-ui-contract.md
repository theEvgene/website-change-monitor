# Согласовать контракт настроек, health и интерфейса

## Question

Какие минимальные изменения нужны в HTTP-контракте и текущем React-интерфейсе, чтобы два зависимых переключателя, автоматическая перепроверка Telegram, зелёное состояние системы при отключённом канале, серая карточка Telegram и нейтральные подписи доставки оставались согласованными без изменения поведения `doctor`?

## Answer

Новые маршруты и новый UI-раздел не нужны. Один server-scoped runtime-модуль
становится владельцем настроек и состояния перехода, а существующие
`/api/settings/notifications`, `/api/telegram` и `/api/health` становятся его
интерфейсами для React и автоматизации.

`GET /api/settings/notifications` и успешный `PUT` возвращают полный effective
state:

```json
{
  "telegramEnabled": true,
  "notifyWhenUnchanged": false,
  "telegramPhase": "enabled"
}
```

`telegramPhase` принимает `checking`, `enabled` или `disabled`. Update — это
непустой частичный patch из двух boolean-полей, поэтому старый payload только с
`notifyWhenUnchanged` остаётся валиден. Противоречивое сочетание с выключенным
Telegram нормализуется к обоим выключенным значениям. Включение немедленно
запускает generation-safe проверку доступности; HTTP-команда завершается
актуальным effective state. Выключение, пришедшее во время проверки, побеждает.

Telegram-state в `/api/telegram` и поле health расширяется четырьмя состояниями:
`available`, `unavailable`, `checking`, `disabled`. Верхний health остаётся
`ready` при `available` и `disabled`, а при `checking` и `unavailable` —
`degraded`. Presentation различает их: checking показывается нейтральной
loading-плашкой, unavailable — warning. Повторная ручная проверка при disabled
не запускает sender и возвращает disabled.

В модалке настроек появляются два переключателя:

1. «Отправлять уведомления в Telegram».
2. «Уведомлять при отсутствии изменений».

Дочерний переключатель доступен только при включённом главном и после завершения
текущего update/checking. Выключение главного автоматически выключает дочерний;
повторное включение не восстанавливает прежнее значение. При ошибке HTTP
последнее подтверждённое состояние сохраняется, а ошибка показывается
существующим toast, не подписью возле переключателя.

При disabled верхняя плашка остаётся зелёной «Система готова». Telegram-карточка
становится серой, показывает «Telegram отключён» и точную подпись
«Уведомления через Telegram отключены в настройках.». В ней нет warning,
причины ошибки, recheck или перехода в настройки. При available/unavailable
сохраняется текущее поведение.

`doctor` не подключается к runtime-модулю и всегда продолжает независимо
проверять Telegram sender. SQLite-настройка из migration 009 остаётся
неиспользуемыми legacy-данными. Полный контракт, поток данных и матрица из
30 автоматизированных сценариев:
[Контракт runtime-настроек, health и интерфейса Telegram](../research/03-health-settings-ui-contract.md).
